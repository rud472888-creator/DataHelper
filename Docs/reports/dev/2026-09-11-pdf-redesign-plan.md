## Frozen data contract

Reader: DIT/data manager, camera/postproduction handoff recipient, and operator investigating failed sampled captures.

Purpose: identify processed clips, review representative frame images, inspect all sampled extraction positions/timecode provenance and source metadata, and find actionable warnings/errors. This is sampled frame extraction and metadata reporting. It does not establish successful decoding of every frame, checksum equality, original-versus-replica metadata equality, color accuracy, or an independent semantic QC result.

Source of truth: the materialized `tuple(items)` of `ReportItem`, the supplied `BatchSummary`, and `AppSettings` passed to the public renderer. `batch_runner` supplies the same `BatchReport.items` to PDF and manifest writers after optional still export. No re-probing media, reading transient UI values, rescanning inputs, reordering clips, changing capture selection, or recalculating timecode in the renderer.

Scope and order: include every supplied item, including failures, skipped/degraded clips, and zero-capture placeholders, in input tuple order. Within an item preserve canonical `Start`, `Mid1` through configured maximum, `End` order. Group only by clip. Never filter successful clips or synthesize extra capture rows. The summary may describe a caller-supplied scope; show its provided values rather than silently replacing them. If supplied total differs from rendered item count, label the rendered count separately. Fix inconsistent test summaries with `build_batch_summary`, not production counting semantics.

Report fields and order:

1. Full project name (`settings.report.project_name` else output stem), report purpose, generation time in local offset-aware ISO-like form `YYYY-MM-DD HH:MM:SS +0900` (actual local offset), report layout, source scope, capture profile, configured middle count, requested-position preference, input recursion and extension filters. Render the input list in settings order using the path-display policy. Do not expose only a truncated common-root summary.
2. Supplied `BatchSummary.status`, `total_clips`, `success_count`, `partial_success_count`, `probe_failed_count`, `decode_failed_count`, and `skipped_count`. Preserve the builder's categories: metadata-incomplete contributes to partial, unsupported/dependency-missing to skipped. Do not present these buckets as newly performed validation. Separately derive `clips with warnings/errors` by inspecting each item's and captures' messages, and `capture rows / capture status counts` from all captures. Never call unsuccessful-clip totals `warnings`.
3. Clip identity: sequential document number, `clip_id`, full `clip_name`, `logical_clip_name`, `source_path`, ordered `part_files`, `format_family`, and `adapter_name`; `ReportItem.status` must remain explicit even if previews are missing.
4. Media metadata: `container`, `codec`, `file_size_bytes`, `duration_seconds`, `frame_count`, exact `fps_num/fps_den` plus decimal fps, `width`, `height`; camera make/model, reel, camera ID; stored clip `start_timecode`, `end_timecode`, `timecode_source`, and `tc_drop_frame`. Label clip timecode range independently from sampled actual timecodes so fallbacks do not overwrite stored facts.
5. All capture evidence: `label`, `requested_ratio`, `requested_frame_index`, `requested_seconds`, `actual_frame_index`, `actual_seconds`, `actual_timecode`, `actual_timecode_source`, `duplicate_of`, `status`, and exported still reference if present. The actual values must not be replaced by requested values or by the referenced duplicate's data. For skipped duplicates show `duplicate_of` explicitly. Temporary image paths are an internal renderer input and are not printed as durable handoff references; exported paths follow path-display settings. All actual/requested values remain visible whether image decoding succeeds or fails.
6. All item warnings and errors, plus capture warnings and errors scoped by capture label, preserving message order. Errors include code, full message, and all `detail` keys/values. `report_builder` aggregates some capture warnings/errors into the item, so label the item list `Report messages` rather than claiming all messages originated at clip level. Repeated aggregate/capture entries may be clearly scoped; do not invent distinct-incident counts from duplicates or discard capture provenance.
7. Complete `clip.metadata_raw`, including nested mappings/lists and missing values, deterministically sorted by mapping key. No key-count limit, line limit, or ellipsis. Flatten nested values into reversible key paths/indexed rows or use pretty JSON paragraphs that can continue across pages. Preserve scalar type/value representation; escape text markup. Empty mapping/list are `{}`/`[]`; `None` is a marked missing value rather than an invented zero.

Formatting: unknown model values use `-`, with a brief legend. Explicit false/zero values remain `아니요 / false` or `0`, never missing. Integers use grouping as appropriate, with raw numeric meaning retained; bytes show exact count and optionally IEC display. Durations/times show seconds with at least three decimals and do not imply exact equality when rounded. Ratios show at least three decimals; fps includes exact rational value. Status and timecode-source labels may use concise natural Korean with the machine enum in parentheses for audit. Timecodes preserve their source string, including semicolon/drop-frame punctuation or elapsed fallback prefixes. Plain prose should use Korean word boundaries; file paths, URLs, and identifiers may break at explicit token boundaries or characters without deleting content.

Path display: retain `_display_path` public behavior: `full` prints full path; `basename` prints filename; `hidden` prints `hidden (filename)`. Apply it consistently to explicit input/source/part/still-reference paths. Do not leak complete paths through compact headers or PDF metadata when hidden/basename is selected. Raw metadata remains the stored payload, not a new filesystem scan; if raw path fields are displayed, apply the same path policy to recognized path keys and record that presentation transform. Do not mutate the raw mapping or sidecar semantics.

Paired outputs: CSV/JSON writer, schemas, ordering, values, null semantics, output flags, still exports, and JSON serialization remain unchanged. Their rows contain fewer metadata fields than the complete in-memory model; do not claim the sidecars contain omitted PDF raw metadata. Prove PDF `(clip_id, capture_label)` sequence equals `build_manifest_rows(items)` for supplied records, including a zero-capture clip identity row. All three representations use the same item tuple.

Debug policy: fixture filenames and project title include `DEBUG DATA` or `테스트 데이터`; repeat a short fixture marker in the body. There is no production debug model field, so do not infer debug state from ordinary source filenames or add a new automatic production marker.

## Document architecture and visual rules

Keep `render_pdf`, `render_contact_sheet_pdf`, and `render_detail_pdf` signatures and dispatcher semantics unchanged. Keep `ReportLayout.CONTACT_SHEET == contact_sheet`, `CLIP_DETAIL == detail`, `PathDisplayMode`, capture settings, and all output flags unchanged. Private layout helpers and coordinate-test assumptions may be replaced. Preserve useful pure selection/path/image-fit behavior where applicable.

Use ReportLab Platypus `BaseDocTemplate`/`PageTemplate` (or `SimpleDocTemplate` when sufficient), `Paragraph`, `Table`/`LongTable`, `Spacer`, rules, and semantic page breaks. Canvas is limited to bounded header/footer decorations and page numbering; main content never uses arbitrary `drawString` positions. Build a small pure presentation projection first, then feed one document story. Avoid a giant unbreakable clip table or `KeepTogether` wrapping an entire clip.

Retain A4 portrait for contact layout and landscape Letter for detail to preserve settings expectations. Contact uses a concise representative triptych and complete evidence below; detail offers larger images for every supplied capture. Both layouts carry the same information and explicit scope. Prefer 42pt side margins and at least 40pt usable top/bottom reserves, 9-10pt body with 1.4-1.5 line leading, 8pt minimum supporting labels, 14-18pt section titles, and 28-32pt cover hierarchy. White `#FFFFFF`, graphite `#20282B`, muted text `#5C696C`, teal `#0B5B61`, rules `#D4DEDF`; no beige sheets, grey full-page background, colored cards, shadow, or rounded pill system. Text carries status meaning, independent of color.

When `include_summary_page=True`, open with a useful compact cover/summary containing the full title, source scope, meaningful count strip/table, issue overview, and validation scope. Continue long scope text safely. When false, omit the dedicated cover while keeping essential title/scope/legend and compact counts at the beginning; do not omit any clip evidence. For zero items create one intentional empty-report document with supplied summary and `보고서에 포함할 클립이 없습니다.` No accidental blank page.

Then in item order: clip heading/identity, ruled media metadata, representative images, complete capture-evidence table, scoped messages, raw metadata. Contact primary images retain Start / representative Middle / End selection: representative middle is the existing nearest requested-ratio-to-0.5 selection, ties retain tuple order. Label it `중간 (Mid2, 3개 중 대표)` as applicable. All Mid rows still appear in the evidence table. If no middle was requested, say `중간 캡처 미설정`; never display `1 of 0`. Detail shows every available capture image in order, with Start/Mid/End identity.

Images use aspect-fit after EXIF orientation, from exported path before temporary path as the existing helper does. Preserve the entire image, never crop/stretch; source and exported stills are read-only. Read once per selected image where feasible, cap embedded preview dimensions (existing 1600px/quality 86 policy is reasonable), and embed only preview-size data. Contact triptych uses three columns with aligned image tops and a bounded maximum height; portrait and panorama stills may have different natural bottoms. Detail can use two columns or one large image when required. Keep each caption and image as one bounded semantic unit. Do not make an image row taller than the usable page.

Missing/corrupt images have a quiet ruled placeholder of intentional size containing `미리보기 없음` plus reason (`캡처 미설정`, `파일 없음`, `이미지 읽기 실패`, or capture failure status). A success capture with a broken image must remain extraction status success while image availability is separately reported. Do not silently convert it into a successful preview or a new extraction failure.

Capture evidence can use five columns: capture/status; requested ratio/frame/seconds; actual frame/seconds; actual timecode/source; duplicate/export reference. Paragraph cells and explicit widths must keep text readable. Metadata uses label/value pairs, with full-width value rows for long paths, notes, and raw values. Ruled rows, modest padding, and repeating header rows are preferable to dense full grids. `splitInRow=1` is available in installed ReportLab 4.5.0; use it or separate paragraphs for a single long value that exceeds a page. Preserve whole short semantic rows and allow long prose continuation rather than throwing a `LayoutError`.

`include_failed_section=True` adds a compact issue index for every non-success item, referring to its numbered clip section and including full messages if it is the only message location. It does not remove inline evidence. `False` removes only this repeated index. Warnings on successful clips remain in the clip section and in correctly defined summary counts. Let the section paginate normally; compute page numbering from the final story. Prefer bounded `Page N` throughout if reliable `N / total` would require fragile replay, or use a proper two-pass build for totals. Each continuation page identifies the project and clip/section where practical; never place a lone heading at the foot of a page.

Set PDF document title to the full project/report title, author/creator to Data Handler / DataHelper as appropriate, and subject to sampled frame review. Do not include hidden paths in document properties.
