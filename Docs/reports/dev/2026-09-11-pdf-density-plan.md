## Frozen compact contract

- Reader/purpose: a DIT or handoff recipient identifies a clip, checks sampled frame appearance and actual positions, and sees actionable failure/warning state quickly. This is sampled capture reporting, not full decode, checksum, replica equality, or color validation.
- Source/scope/order: materialize the supplied `ReportItem` iterable once; retain every clip in input order and every supplied capture in its original canonical order. Use supplied `BatchSummary` as supplied, separately label rendered count on mismatch. Do not probe media or alter capture selection, stored values, adapters, or models.
- Grouping: one bounded horizontal row per clip; three rows per page, starting on page 1. No cover, appendix, separate issue index, repeated detail/evidence section, or per-clip page break. Empty input produces one intentional empty-state page.
- Missing values: `-`; preserve real zero/false. Timecode punctuation and elapsed fallback remain distinguishable. Show extraction status separately from preview availability; a missing picture cannot silently become extraction success/failure.
- Pairing: CSV/JSON schemas, rows, values, flags, filenames, and writers remain unchanged. Compare ordered `(clip_id, capture_label)` with `build_manifest_rows`, including zero-capture identity records. PDF is now a deliberately compact projection of the same items, not a claim to contain every model field.
- Debug: fixture filenames/title/body say `DEBUG DATA` or `테스트 데이터`. Do not infer a production debug flag from media paths.

Each clip row contains:

1. Document number, clip name, stable clip ID, clip status, and warning/error counts. Normal names/IDs remain complete; preserve a recognizable filename suffix and document number when an exceptional name must be abbreviated.
2. Compact normalized metadata: format/container/codec; resolution; exact fps rational and useful decimal; duration and frame count; file size with unit; camera make/model, camera ID/reel; stored start/end TC with TC source and drop-frame meaning. Group short values on labeled lines rather than rendering one table row per field. Include source path under the existing display policy, logical name when different, and split-file count. Adapter can share the format line. Empty optional camera/adapter-style fields can be combined into a single `-` group.
3. Meaningful aspect-fit frame thumbnails. Contact: Start, the existing nearest-to-0.5 representative Mid, End. With two captures, show Start/End and `중간 캡처 미설정`; do not synthesize a capture. Detail: show every supplied frame, two to five across the available gallery width. All labels stay explicit. Keep EXIF orientation, exported-before-temp source precedence, bounded preview encoding, no crop/stretch, and clear missing/corrupt placeholders.
4. A compact timing/status grid for **all two to five supplied captures**, not only the pictures: label, capture state, requested frame/seconds, actual frame/seconds, actual TC and source. Requested ratio may share the requested-position line. Show duplicate target and absent actual values honestly. Short Korean state/source labels are acceptable when their mapping is explicit; never relabel a supplied failure as success. Normal actual TCs must be fully readable.
5. A bounded message area: report/capture scope, highest-severity error code and useful message excerpt first, then warning excerpt, plus total counts and `외 N건`/`내용 축약` when applicable. Counts inspect item and capture lists, including warnings on success. Do not claim duplicated aggregate/capture messages are distinct incidents. A critical failure state and its capture location must always be visible even if prose is long. Long error-detail payloads and raw dumps are omitted from this PDF by the new scope.

Keep ReportLab Platypus, existing bundled regular/bold Korean fonts, white/graphite/teal styling, and page dimensions. Compose bounded paragraphs/tables using measured font widths/heights, then place three complete rows. Do not fix density by shrinking text below 8pt or letting clipped content escape a fixed box.

| Contact, portrait A4 | approximately 511 × 745pt | 70pt | 220pt × 3 = 660pt | Shared heading; metadata left approximately 185pt, preview/timing area right approximately 316pt with a 10pt gap. Three preview cells approximately 100pt wide and 56pt high for 16:9. Timing grid below images. |
| Detail, landscape Letter | 708 × 515pt | 65pt | 148pt × 3 = 444pt | Metadata left approximately 242pt, gallery/timing right approximately 456pt with a 10pt gap. Up to five 85pt-wide, 48pt-high 16:9 frames; all-capture grid below. |

The totals fit the current frame: contact 730 < 745pt; detail 509 < 515pt. These are engineering budgets to prove with `wrap()` and PDF output, not a claim that arbitrary unbounded values fit. Running footer/header use the existing reserved space. Later pages retain the same three-row rhythm; do not enlarge them into a different report style.

Use 10-11pt clip headings, 8.5-9pt core text, and **8pt minimum** supporting/capture text with approximately 11pt leading. Main timing columns should carry short machine-like values; use two compact lines per capture where needed, not sentence-heavy five-column cells. A landscape timing grid can use one line per capture with more columns. Contact's 5-capture grid, gallery, and heading must fit within the 220pt row after padding. Measure both the 2- and 5-capture cases; do not use a zero-capture fixture as density evidence. Portrait/panorama image content may naturally be narrow/short under aspect-fit; gallery allocation does not expand the row.

The intro is a compact integrated title/count strip: project, generated local date/time, rendered/summary status counts, capture total, warning/error clip counts, brief sampled-review legend. Normal long Korean title gets up to two lines. Move verbose configuration prose out of the PDF; retain concise capture profile/input scope as space allows. `include_summary_page=True` means the fuller integrated summary within the budget; `False` means a lean title/legend. Neither starts a cover. `include_failed_section=True` adds bounded issue emphasis/counts inside the existing intro/clip rows; `False` omits that optional emphasis, never the clip/capture failure states or essential messages. Keep the field names/defaults accepted and document these intentional presentation changes. Preserve public `render_pdf`, `render_contact_sheet_pdf`, `render_detail_pdf`, dispatch, enum values, page sizes, capture settings, and output flags.

## Long values and omissions

Apply `full`/`basename`/`hidden` **before** measuring or abbreviating all explicit paths and references. `full` continues to select the full path as its source display value; extraordinary lengths can show an explicitly marked excerpt. Do not reveal hidden prefixes in headers, document metadata, PDF links, tooltips, or abbreviations. Do not add full raw payloads to invisible PDF objects to bypass the user's no-appendix request.

Budget heading/identity and message lines explicitly. Use Korean word boundaries for prose and safe token/character breaks for paths/IDs. When an exceptional field exceeds the budget, visibly mark `축약` and retain identification suffix/prefix where meaningful. Show complete normal critical states and actual TCs; exceptional TC source strings may abbreviate with a marker. All supplied captures still get visible status/timing entries and the clip still gets a full row. Do not create overflow pages or silently discard further clips.

Only direct a reader to a companion output when its flag is enabled, and only for fields the existing writer actually includes. CSV/JSON contain full clip names/IDs/paths and warning/error **message strings**; JSON additionally contains normalized media and duplicate targets. They do **not** preserve `metadata_raw`, camera/reel fields, part-file lists, or structured error detail/code universally. Never promise that all PDF omissions are recoverable from them. The new PDF intentionally excludes full raw metadata and error-detail dumps, with no manifest-schema expansion. If companions are disabled, say only `내용 축약` rather than inventing an available full-value destination.
